# 04 · 关键决策记录(ADR)

> 本文件记录重构中的关键技术决策**及其理由**,并明确列出与旧版的**行为变更**。
> 新增决策请追加到第十节,格式保持一致。

---

## 一、技术选型决策

### ADR-001 · 后端使用 Go

**决策**:全量重写为 Go 1.24+。

**理由**:
- 单静态二进制,部署只需一个容器 + 一个二进制,无 Node 运行时依赖;
- `net/http` + `chi` 组合足够承载认证服务,无需重量级框架;
- 原生并发模型适合 IO 密集的认证场景;
- 强类型 + 编译期检查,消除旧版依赖运行时校验的隐患。

**代价**:团队需要 Go 技能;无法复用旧版 TypeScript 代码。

---

### ADR-002 · PostgreSQL 替代 SQLite

**决策**:使用 PostgreSQL 16+,通过 `pgx/v5` 驱动 + `sqlc` 查询。

**理由**:
- 旧版 SQLite **强制单实例部署**(官方文档明确「不要加 replicas」),这是不可接受的扩展性瓶颈;
- PostgreSQL 支持水平扩展、高并发、连接池;
- 原生支持 schema 隔离、JSONB、部分索引,比 SQLite 迁移更平滑;
- sqlc 把 SQL 编译成类型安全的 Go 代码,兼顾显式 SQL 与类型安全。

**代价**:需要额外部署一个 PostgreSQL 实例(已用 docker-compose 编排)。

**保留的隔离手段**:旧版用「4 个 SQLite 文件」做域隔离,新版改用 **4 个 PostgreSQL schema**:

| schema | 用途 |
|---|---|
| `identity` | 账号、凭据、会话、RBAC、审计 |
| `oidc` | OIDC 客户端、授权码、令牌、同意记录、签名密钥 |
| `minecraft` | 玩家档案、别名、MC 令牌、材质、签名密钥 |
| `app` | 应用配置项 |

域之间通过权限控制隔离,而不是靠文件边界。

---

### ADR-003 · OIDC 使用 ory/fosite,不自研

**决策**:用 `github.com/ory/fosite` 作为授权服务器内核。

**理由**:
- OAuth 2.1 / OIDC 的实现细节(授权码、PKCE、令牌轮换、撤销、introspection、JWKS 生成)极其容易出**安全漏洞**;
- fosite 是社区最成熟的生产级实现,经过大规模验证,遵循 RFC 6749/6750/7009/7636/9126 等;
- 自研意味着自己承担全部安全责任,风险不可接受。

**代价**:学习曲线较陡;库的行为需要时间熟悉;依赖树较重。

**缓解**:先跑通官方 example 再集成;把 fosite 的存储接口适配到我们的 schema,业务逻辑仍在自己的层。

---

### ADR-004 · 会话按用途拆分,不按域混存

**决策**:`session` 表只存终端用户登录态;OIDC 与 MC 用各自独立的令牌表。

**理由**:
- 旧版 `session` 表用 `domain` 字段混存四种语义(`sso` / `oauth` / `mc` / `admin`),字段含义随调用方变化,极易出错;
- MC 令牌必须与 OAuth 令牌在**存储、签名密钥、校验逻辑**上完全隔离,混存表无法保证;
- 拆表让每个表的语义唯一,索引和约束都能精确表达。

**影响**:新增三张表,查询时需要明确知道自己在处理哪种令牌。

---

### ADR-005 · 统一为单一 RBAC 模型

**决策**:删除 `admin_*` / `mc_*` / `oauth_*` 六张角色表,统一为 `role` / `permission` / `role_permission` / `account_role` 四张表,单一权限点命名空间。

**理由**:
- 旧版两套并行 RBAC 从未定义清楚职责边界,且需要双份维护;
- 权限点命名空间重复(`admin:mc:profile:read` 与 `minecraft:profile:read` 语义重叠);
- 「域管理员」与「平台管理员」的差异本质是**持有的权限点不同**,不是模型不同。

**行为变更**:后台接口的权限点名称改变,详见 [05-api.md](./05-api.md)。

---

### ADR-006 · 前端产物 go:embed 进二进制

**决策**:用 `embed.FS` 把 Vue 构建产物编进 Go 二进制,由 Go 直接托管静态文件。

**理由**:
- 旧版后端**不托管任何静态文件**,nginx 是必需组件,增加了部署复杂度;
- 嵌入后单进程即可服务前端,容器镜像更小,部署更简单;
- 配合 `embed.FS`,构建产物与二进制版本天然一致,不会出现前后端版本错配。

**代价**:每次改前端都要重新构建 Go 二进制(通过 Makefile 自动化)。

**保留**:生产环境仍建议用 nginx 终结 HTTPS(见 [08-deployment.md](./08-deployment.md)),但它变成**可选**的优化而非必需组件。

---

### ADR-007 · 皮肤文件本地磁盘存储

**决策**:皮肤/披风存本地磁盘,通过 `storage.Storage` 接口访问,本期不实现 S3 后端。

**理由**:
- 用户明确选择只支持本地磁盘;
- 接口化设计让未来加 S3 只需新增一个实现,不改调用方;
- 开发环境零外部依赖。

**代价**:多实例部署时皮肤文件不共享,需挂载共享存储或接受粘性会话。这是明确接受的限制。

---

### ADR-008 · 统一响应包格式

**决策**:所有 JSON 接口返回 `{"code":0,"message":"ok","data":{...}}`,非 0 为错误。

**理由**:
- 与旧版保持一致,前端错误处理逻辑可平移;
- 错误码语义明确,不依赖 HTTP 状态码传递业务语义(HTTP 状态码仍正确设置)。

---

### ADR-009 · sqlc + goose 数据访问与迁移

**决策**:SQL 用 sqlc 编译成类型安全的 Go 代码,迁移用 goose 管理版本。

**理由**:
- sqlc 保持 SQL 显式可读,不被 ORM 抽象隐藏,同时提供编译期类型检查;
- goose 迁移工具成熟,支持 up/down/版本追踪;
- 认证系统对 SQL 精确性要求高,ORM 的隐式行为是风险来源。

**约束**:`make sqlc` 生成物必须提交,CI 校验生成物与查询定义一致。

---

### ADR-010 · 保留术语门禁思想

**决策**:`internal/identity` 和 `internal/platform` 的源码中禁止出现 `oidc` / `mc` / `minecraft` / `skin` 等业务词。

**理由**:
- 旧版用 `scripts/check-terms.mjs` 强制内核不含业务语义,这个思想是对的,防止内核长出业务耦合;
- 用 CI 中的 `grep` 检查替代脚本,实现更轻。

**说明**:与旧版不同的是,Go 侧**移除了「域插件注册中心」**这套运行时校验(见 ADR-011),域装配改用编译期依赖注入。术语门禁仍保留,因为编译期无法阻止你在内核里写 `if domain == "mc"`。

---

### ADR-011 · 移除运行时域注册机制

**决策**:废弃旧版的「域插件注册中心 + 启动期反射校验」,改为编译期显式装配。

**理由**:
- 旧版需要 `AuthDomainPlugin` 接口 + `forRoot()` 动态模块 + 启动时校验 issuer/keyPurpose 唯一性,是因为 NestJS 依赖注入容器要求运行时注册;
- Go 侧在 `main.go` 里显式 import 三个域并注入依赖,少一个域编译就失败,**不需要运行时校验**;
- 少一层抽象,代码更直白,调试更简单。

---

## 二、行为变更清单(与旧版不兼容之处)

以下是**有意为之**的变更,其余功能与旧版兼容。

| # | 变更 | 旧版 | 新版 | 影响 |
|---|---|---|---|---|
| C-1 | 密码长度策略 | 6–18 位 | **8–128 位** | 旧密码仍可登录;新注册按新策略 |
| C-2 | 密码复杂度 | 强制大写+小写+数字 | 不强制组合,查泄露库 | 注册规则放宽 |
| C-3 | RBAC 模型 | 两套表,两个命名空间 | 单一表,统一命名空间 | 后台权限点名称改变 |
| C-4 | 会话表结构 | 一表混存四种 domain | 按用途拆三张表 | 无外部可见影响 |
| C-5 | `organization` | 建表但未使用 | 删除 | 无影响 |
| C-6 | 数据库 | 4 个 SQLite 文件 | 1 个 PostgreSQL,4 个 schema | 部署形态变化 |
| C-7 | 静态文件 | 必须 nginx 托管 | Go 可直接托管(nginx 可选) | 部署简化 |
| C-8 | MC 登录开关 | `REGISTRATION_MC_LOGIN_DEFAULT` | 保留 `MC_LOGIN_DEFAULT` | 语义不变 |
| C-9 | 令牌类型 | 统一 `session.domain` 区分 | 独立表,独立签名密钥 | 无外部可见影响 |
| C-10 | 邮箱唯一性 | 不强制 | **强制唯一** | 需数据迁移检查 |

**C-10 说明**:新版本强制一个邮箱对应一个账号,避免找回密码歧义。如果旧库有重复邮箱,迁移前需人工处理。

## 三、待定事项

以下问题在重构过程中可能需要进一步决策,记录于此:

1. **Minecraft 改名策略**:改名后旧名保留多久?是否允许抢注别人腾出的名字?需要产品决策。
2. **会话并发上限**:一个账号最多允许多少个活跃会话?超出后踢最早的,还是拒绝登录?
3. **SSO cookie 作用域**:默认按父域共享,如需更严格隔离可改为仅终端用户站。
4. **MFA(两步验证)**:本期不做,但架构上会话表可扩展预留。
